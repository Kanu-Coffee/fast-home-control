# Dev / Main 정책

- 개발 소스와 앱 저장소는 `dev` 브랜치다. 버전은 `0.1.0-dev.1`처럼 표시하고 GitHub prerelease를 사용한다.
- 첫 Dev는 앱 디렉터리의 Dockerfile로 Supervisor가 소스 빌드한다. amd64/aarch64를 선언한다. 별도 GHCR 인증이나 패키지 공개 권한 설정을 설치 사용자에게 요구하지 않는다. 사전 빌드 이미지 배포는 후속 최적화다.
- Checks가 통과한 dev 소스를 실제 HAOS에 설치·기동 검증한 후 검증된 앱 소스를 포함하는 commit에 `v<version>` 태그와 prerelease를 만든다. 검증 후 문서·캡처만 추가할 수 있으며 앱 소스가 바뀌면 다시 검증한다. amd64와 aarch64의 컨테이너 빌드를 CI에서 검사한다.
- 릴리스 설명에 지원 범위, 실제/모의 검증 구분, 알려진 제약을 기록한다. 치명적 문제는 이전 버전 재설치 또는 다음 Dev 수정 버전으로 복구한다. HA 백업 기능을 활용한다.
- `main` 반영과 stable slug/image 및 정식 릴리스 생성은 사용자 명시 승인 이후 진행한다. 첫 Dev를 안정 버전으로 자동 승격하지 않는다.
- API 키, 테스트 HA 토큰, VM 디스크와 실행 이력은 Git 및 컨테이너 빌드 컨텍스트에서 제외한다.
