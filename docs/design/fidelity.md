# UI 구현 비교 기록

이미지 콘셉트와 실제 Supervisor Ingress 렌더링을 직접 비교했다. 최종 캡처: [desktop.png](desktop.png), [mobile.png](mobile.png). 기준: [concept.png](concept.png).

| 비교점 | 구현 |
|---|---|
| 구성 | 헤더 → 제목/입력 → 예시 → 이력·연결 → 허용 범위 순서를 유지 |
| 폭·여백 | 데스크톱 약 1160px 중앙 콘텐츠, 넓은 여백 유지. 실제 진단 문구로 세로 길이는 증가 |
| 입력 | 테두리 입력창, 우측 하단 초록 실행 버튼, 아래 3개 예시 버튼 유지 |
| 패널 | 얇은 테두리와 작은 모서리, 이력/연결 1.6:1 배치 유지 |
| 색상 | 흰 배경·짙은 본문·회색 보조문구·녹색 제어 강조 유지 |
| 모바일 | 390px에서 패널을 한 열로 배치. 입력·실행·도메인 스위치 접근 가능, 가로 넘침 없음 |
| 글꼴 | 별도 웹폰트 다운로드 없이 시스템 글꼴 사용. 콘셉트 대비 제목의 굵기·폭에 차이 있음 |

콘셉트의 가상 실행 이력과 숫자를 실제 API 결과로 교체했다. “실행 완료”는 “HA 명령 수락”으로 바꾸고, 물리 기기 완료 보장이 아니라는 문구를 넣었다. Azure 연결 행을 추가했다. 아직 제공하지 않는 “상태 조회” 스위치를 활성화해 표시하지 않는다. 지원 도메인을 먼저 표시하고 발견된 미지원 도메인은 접어서 확인할 수 있게 했다. 첫 Dev 범위·데이터 전송 안내와 수동 재탐색 결과를 추가했다. 이 차이는 실제 지원 범위와 상태를 정확하게 전달하기 위한 것이다.

브라우저 검증은 로컬 Playwright Chromium으로 실제 Ingress에서 수행했다. 명령 제출/수락, 도메인 해제/복구, 수동 탐색, 모바일 넘침을 확인했다.
